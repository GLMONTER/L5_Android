# Android 17 for the Purism Librem 5

AOSP 17 (`android-17.0.0_r1`) for the Librem 5 r4 (Evergreen, i.MX8MQ), built on Purism's
kernel and u-boot, on GloDroid's graphics stack (Mesa etnaviv, drm_hwcomposer, minigbm) and on
libcamera for the cameras.
This repository is the whole port: device tree, HALs, patches to upstream projects, kernel
patches and config, and the scripts to build and flash. Nothing else is modified by hand.

| Battery/charging, buttons, vibration | |

| Suspend/resume | deep suspend works, but the phone occasionally hangs after a resume (being investigated, see Power below) |
| Modem (BM818): radio HAL, IMEI/baseband, SIM state, airplane mode; Phone + Messages | AT-command AIDL HAL in `librem5/radio` (fork of goldfish's ranchu HAL) |

PCM <-> codec), headphone jack (detection enabled, untested), hardware video decoding (Hantro
G1/G2: no V4L2 stateless Codec2 component yet; the SoC has no video encoder), HDMI.

Known gaps: `scripts/setup.sh` has not been run end to end on a fresh machine yet (everything
after it has); the build depends on Purism, GloDroid, freedesktop and Debian keeping the
pinned revisions/URLs available.

## Layout

```
manifest/librem5.xml   local manifest: AOSP + GloDroid/Mesa/minigbm/drm_hwcomposer pins + this repo
patches/<project>/     patches for AOSP/GloDroid projects (scripts/apply-patches.sh, git am)
kernel/                Purism kernel pin, PureOS base config + Android fragment, kernel patches
librem5/               device tree: product/board config, fstab, init, sepolicy, and the HALs:
                       audio, sensors, lights, power, radio, gnss, camera (provider + libcamera
                       config), hks (kill switch monitor); codecs (media codec seccomp policy)
librem5-kernel/        kernel prebuilts, generated by scripts/build-kernel.sh (not committed)
librem5-firmware/      Broadcom firmware, fetched by scripts/extract-firmware.sh (not committed)
boot/                  u-boot (Purism, for RAM boot), uuu script, flash initramfs init
scripts/               setup, build, flash
```

## Boot and partition layout

Purism's u-boot (in eMMC boot0, untouched) has no Android boot commands, so the eMMC user area uses:

| # | name | size | contents |
|---|---|---|---|
| 1 | bootfs | 256 MiB | ext4: Image, DTB, combined ramdisk, boot.scr, flash initramfs |
| 2 | misc | 512 KiB | bootloader message |
| 6 | frp | 512 KiB | factory reset protection |
| 3 | metadata | 16 MiB | |
| 4 | super | 6 GiB | system, system_ext, product, vendor, vendor_dlkm (slot _a) |
| 5 | userdata | rest | file-based encryption (fscrypt v2) |

u-boot's distro boot runs `boot.scr` from partition 1. If `/flashmode` exists on bootfs it boots
the flash initramfs instead, which is how `scripts/flash.sh` updates without button presses.
There is no AVB (u-boot cannot verify) and no metadata encryption (needs dm-default-key).

## Building

Host: Ubuntu/Debian x86-64, ~250 GB free disk, RAM + swap >= 96 GB (Soong analysis of this
tree peaks around 60 GB; 32 GB RAM + 64 GB swap works).

```sh
git clone <this repo> librem5-android
librem5-android/scripts/host-setup.sh           # packages, repo/adb/fastboot, swap, udev, USB net
librem5-android/scripts/setup.sh ~/l5           # repo sync (~110 GB), patches, Python venv
cd ~/l5/aosp/device/purism                      # work in the synced copy from now on
scripts/extract-firmware.sh                     # Broadcom firmware from Purism's repo (pinned)
scripts/build.sh                                # kernel + Android + images in ~/l5/out/images
```

The Wi-Fi/Bluetooth firmware is non-free and not part of this repo. `extract-firmware.sh`
fetches it from Purism's public `firmware-brcm43752-nonfree` repo at a pinned commit and checks
it against the files an r4 ships with.

After `repo sync`, run `scripts/apply-patches.sh` again (sync resets the patched projects).

## Flashing

USB networking: the flash initramfs is `10.66.0.1`; give the host's `cdc_ncm` interface
`10.66.0.2/24` (e.g. a NetworkManager profile matching driver `cdc_ncm`).

- **First install** (erases PureOS): power off, hold Volume-Up while plugging in USB (download
  mode), then `scripts/flash-first.sh` and type `WIPE`.
- **Updates**: with Android running and adb connected, `scripts/flash.sh`. Keeps your data.
- **Recovery** if Android doesn't reach adb: download mode, then `scripts/flash-first.sh --update`.

Every write is verified by SHA-256 on the phone. Download mode never depends on the eMMC
contents, so the phone can always be recovered.

## Notes for porters

Hardware quirks found during bring-up (details in commit messages and file comments):
- LSM9DS1 accel and gyro report all axes negated; the DT mount matrix is wrong (overridden by
  `ro.vendor.sensors.*.mount_matrix`). Accel/gyro share one ODR; >= 119 Hz tears gyro reads.
- The VCNL4040 sits behind dark glass: use the longest ALS integration time.
- The DT had no Bluetooth node (PureOS uses hciattach); kernel patch 0003 adds a serdev node.
  BT_REG_ON is shared with Wi-Fi, so there is no shutdown GPIO and hci_bcm stays at 115200 baud,
  too slow for A2DP; patch 0005 honours the DT max-speed. hci_uart loads after wlan0 exists
  (brcmfmac resets the shared chip).
- LSM9DS1 magnetometer axes: mount matrix -1,0,0;0,1,0;0,0,-1 (verified).
- BM818: AT on /dev/ttyUSB2 (ttyUSB1/3 also answer), QMI data on wwan0. Without a SIM the
  firmware rejects most network commands with a bare ERROR (even AT+CSQ). Its AT port appears
  before the firmware answers, so the HAL retries init. Data calls use AT+CGACT +
  AT$QCRMCALL (untested).
- memfd: kernel patch 0004 (upstream backport) + the memfd_class policy capability; minigbm's
  shared metadata region is then an allocator memfd that every graphics client maps.
- Android 17 needs `CONFIG_CPUSETS_V1`, `sys.use_memfd=true` (no ashmem upstream), and an audio
  HAL with modules for every instance its VINTF declares, or system_server never finishes booting.
- Cameras: the i.MX8MQ has no ISP, so libcamera's software ISP debayers on the CPU (4 threads,
  `librem5/camera/configuration.yaml`). Its GPU debayer works but is slower on the GC7000L.
  FCM 8 only accepts AIDL camera providers and AOSP has no wrapper for camera3 HAL modules any
  more: `librem5/camera/provider` is the AIDL wrapper from raspberry-vanilla's libcamera port.
  The software ISP outputs one stream, so the HAL derives the others from it. Contrast AF drives
  the DW9714 voice coil; tuning (black level, colour matrix from Purism's Millipixels data,
  AF range) is in `librem5/camera/*.yaml`. Kernel patches fix the HI846 pixel rate and the
  camera rail start-up delay.
- Android 17's flashlight tile only turns on a torch that has strength levels.
- GNSS: the DT calls the receiver "globaltop,pa6h" (kernel gnss-mtk, 9600 baud) but it is an ST
  Teseo (`$PSTM` sentences; GPS + GLONASS, two GNGSA per epoch without system ids). AOSP's
  default GNSS HAL only simulates; `librem5/gnss` parses the NMEA. Android 17's GNSS JNI calls
  into every extension the HAL returns, even the nullable ones, so the HAL returns no-op
  objects for all of them.
- USB: Android only creates its USB device manager (function switching: MTP, PTP, tethering)
  when `/sys/class/android_usb` exists, which comes from an Android kernel patch; kernel patch
  0011 ports it from the Android common kernel (android16-6.12) and accepts the `none` UDC name
  GloDroid's gadget HAL writes. USB drives need the FAT code pages built in (no on-demand module
  loading): vfat mounts failed with "codepage cp437 not found".
- Compass: the LSM9DS1 magnetometer sees a ~750 uT hard-iron offset (the speaker magnet). The
  sensors HAL calibrates it online from each axis' range (turn the phone through all
  orientations once) and keeps the offset in `/data/vendor/sensors` across reboots; calibrated,
  it reads Earth's ~50 uT.
- Video: the software codec service's seccomp policy lacks syscalls Mesa makes when minigbm
  maps a frame (`librem5/codecs/mediaswcodec.policy`), and encoders fed from a Surface need
  `debug.stagefright.c2inputsurface=-1`. Recording stops at 720p: at 1080p the software encoder
  plus the CPU debayer reached only ~9 fps. In dim light the frame rate drops further because
  the auto-exposure lengthens the frames (up to 66 ms within the 15-30 fps range).
- Audio capture: the i.MX SAI runs capture synchronously with playback, so while something
  plays the codec only accepts captures at the playback's 48 kHz stereo (a mono open fails with
  EINVAL, which the audio HAL reports as ENOMEM). The mic input is therefore 48 kHz stereo only
  and AudioFlinger converts.
- Kill switches: Purism's rfkill-hks driver only reported rfkill state; kernel patch 0010 adds
  input switches (SW_MUTE_DEVICE, SW_CAMERA_LENS_COVER), which Android maps to its hardware
  privacy toggles. The Wi-Fi/BT switch power-cycles the combo chip: Bluetooth then needs the
  SDIO host reset and its UART driver reloaded, done by `librem5/hks` + `init.librem5.rc`.
  Android turns Wi-Fi off when its interface vanishes; turn it back on after the switch.

## Power

- **Power HAL** (`librem5/power`): frequency floors on power hints. A touch sets a 1.0 GHz CPU
  floor and the DRAM at its top speed for the hinted time, an app launch the top CPU speed for
  up to 5 s; screen off releases both. Battery saver (`LOW_POWER`) caps the CPU at 1.0 GHz.
  schedutil and the DRAM devfreq governor scale freely above the floors. There is no camera
  floor: the CPU debayer saturates both governors by itself (measured 34.5 ms per 1080p frame
  with and without one).
- **Suspend**: deep suspend (`mem`), woken by the power key, RTC alarms, charger/battery,
  USB-C, the volume keys and the kill switches. 30/30 RTC-woken cycles pass, but in normal use
  the phone has hung a few times shortly after a resume: silently, with no panic or lockup
  report, which on the i.MX8MQ usually means a bus access to an unpowered/unclocked block.
  `watchdogd` (10 s pings, 30 s timeout, paused in suspend) resets a hung phone, after which
  the kernel log of the hang is in `/sys/fs/pstore/console-ramoops-0`. Android lowers the
  console log level after boot, so to catch the culprit set
  `adb shell setprop persist.vendor.librem5.pm_debug 1`: every device's suspend/resume
  callback is then logged into pstore (each suspend takes a few seconds longer; `0` turns it
  off). The last "calling" line without a "returned" names the driver.
- After a watchdog reset the Wi-Fi/BT combo chip is not power-cycled and its Bluetooth part
  stops answering; init therefore always resets the SDIO host before loading Bluetooth (the
  same sequence as after the Wi-Fi/BT kill switch).
- The BCM43752 loses power in suspend and brcmfmac reloads its firmware on every resume
  (~0.45 s). The GNSS receiver is powered only while a location session runs (plus 60 s).
- Battery gauge (MAX17042): `charge_now` is the remaining charge in uAh; `charge_counter` is
  not. Battery drain figures: to be measured.
