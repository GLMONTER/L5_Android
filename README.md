# Android 17 for the Purism Librem 5

AOSP 17 (`android-17.0.0_r1`) for the Librem 5 r4 (Evergreen, i.MX8MQ), built on Purism's
kernel and u-boot and on GloDroid's graphics stack (Mesa etnaviv, drm_hwcomposer, minigbm).
This repository is the whole port: device tree, HALs, patches to upstream projects, kernel
patches and config, and the scripts to build and flash. Nothing else is modified by hand.

## Status

| Works | Notes |
|---|---|
| Display, GPU (GLES 2.0, Mesa etnaviv), touch | mxsfb kernel patch for Android's RGBA buffers |
| Wi-Fi (BCM43752), Bluetooth (BCM4362) incl. A2DP audio | firmware from Purism's repo, see below; BT UART at 1.5 Mbaud (kernel patch 0005) |
| Speaker, microphone | AOSP AIDL audio HAL + WM8962 routing from Purism's UCM profile |
| Accelerometer, gyroscope, compass, light, proximity, auto-rotate, auto-brightness | IIO-backed sensors HAL |
| Status LED, power hints, lock screen PIN | lights/power HALs, nonsecure gatekeeper |
| SELinux enforcing | device policy in `librem5/sepolicy`; `SELINUX_MODE=permissive scripts/build.sh` to debug |
| Battery/charging, buttons, vibration, USB adb | |
| Suspend/resume | works in testing; one unreproduced non-wake seen |

| Modem (BM818): radio HAL, IMEI/baseband, SIM state, airplane mode; Phone + Messages | AT-command AIDL HAL in `librem5/radio` (fork of goldfish's ranchu HAL) |
| Earpiece | WM8962 SPKOUTR (Purism UCM "Handset1") |

Not yet: calls, SMS and mobile data (implemented but untested: no SIM yet), call audio (modem
PCM <-> codec), headphone jack (detection enabled, untested), cameras, HDMI.

Known gaps: `scripts/setup.sh` has not been run end to end on a fresh machine yet (everything
after it has); the build depends on Purism, GloDroid, freedesktop and Debian keeping the
pinned revisions/URLs available.

## Layout

```
manifest/librem5.xml   local manifest: AOSP + GloDroid/Mesa/minigbm/drm_hwcomposer pins + this repo
patches/<project>/     patches for AOSP/GloDroid projects (scripts/apply-patches.sh, git am)
kernel/                Purism kernel pin, PureOS base config + Android fragment, kernel patches
librem5/               device tree (product/board config, fstab, init, sepolicy, audio, sensors HAL)
librem5-kernel/        kernel prebuilts, generated by scripts/build-kernel.sh (not committed)
librem5-firmware/      Broadcom firmware, fetched by scripts/extract-firmware.sh (not committed)
boot/                  u-boot (Purism, for RAM boot), uuu script, flash initramfs init
scripts/               setup, build, flash
```

## Boot and partition layout

Purism's u-boot (in eMMC boot0, untouched) has no Android boot commands, so the eMMC user area uses:

| # | name | size | contents |
|---|---|---|---|
| 1 | bootfs | 256 MiB | ext4: Image, DTB, combined ramdisk, boot.scr, flash initramfs |
| 2 | misc | 512 KiB | bootloader message |
| 6 | frp | 512 KiB | factory reset protection |
| 3 | metadata | 16 MiB | |
| 4 | super | 6 GiB | system, system_ext, product, vendor, vendor_dlkm (slot _a) |
| 5 | userdata | rest | file-based encryption (fscrypt v2) |

u-boot's distro boot runs `boot.scr` from partition 1. If `/flashmode` exists on bootfs it boots
the flash initramfs instead, which is how `scripts/flash.sh` updates without button presses.
There is no AVB (u-boot cannot verify) and no metadata encryption (needs dm-default-key).

## Building

Host: Ubuntu/Debian x86-64, ~250 GB free disk, RAM + swap >= 96 GB (Soong analysis of this
tree peaks around 60 GB; 32 GB RAM + 64 GB swap works).

```sh
git clone <this repo> librem5-android
librem5-android/scripts/host-setup.sh           # packages, repo/adb/fastboot, swap, udev, USB net
librem5-android/scripts/setup.sh ~/l5           # repo sync (~110 GB), patches, Python venv
cd ~/l5/aosp/device/purism                      # work in the synced copy from now on
scripts/extract-firmware.sh                     # Broadcom firmware from Purism's repo (pinned)
scripts/build.sh                                # kernel + Android + images in ~/l5/out/images
```

The Wi-Fi/Bluetooth firmware is non-free and not part of this repo. `extract-firmware.sh`
fetches it from Purism's public `firmware-brcm43752-nonfree` repo at a pinned commit and checks
it against the files an r4 ships with.

After `repo sync`, run `scripts/apply-patches.sh` again (sync resets the patched projects).

## Flashing

USB networking: the flash initramfs is `10.66.0.1`; give the host's `cdc_ncm` interface
`10.66.0.2/24` (e.g. a NetworkManager profile matching driver `cdc_ncm`).

- **First install** (erases PureOS): power off, hold Volume-Up while plugging in USB (download
  mode), then `scripts/flash-first.sh` and type `WIPE`.
- **Updates**: with Android running and adb connected, `scripts/flash.sh`. Keeps your data.
- **Recovery** if Android doesn't reach adb: download mode, then `scripts/flash-first.sh --update`.

Every write is verified by SHA-256 on the phone. Download mode never depends on the eMMC
contents, so the phone can always be recovered.

## Notes for porters

Hardware quirks found during bring-up (details in commit messages and file comments):
- LSM9DS1 accel and gyro report all axes negated; the DT mount matrix is wrong (overridden by
  `ro.vendor.sensors.*.mount_matrix`). Accel/gyro share one ODR; >= 119 Hz tears gyro reads.
- The VCNL4040 sits behind dark glass: use the longest ALS integration time.
- The DT had no Bluetooth node (PureOS uses hciattach); kernel patch 0003 adds a serdev node.
  BT_REG_ON is shared with Wi-Fi, so there is no shutdown GPIO and hci_bcm stays at 115200 baud,
  too slow for A2DP; patch 0005 honours the DT max-speed. hci_uart loads after wlan0 exists
  (brcmfmac resets the shared chip).
- LSM9DS1 magnetometer axes: mount matrix -1,0,0;0,1,0;0,0,-1 (verified).
- BM818: AT on /dev/ttyUSB2 (ttyUSB1/3 also answer), QMI data on wwan0. Without a SIM the
  firmware rejects most network commands with a bare ERROR (even AT+CSQ). Its AT port appears
  before the firmware answers, so the HAL retries init. Data calls use AT+CGACT +
  AT$QCRMCALL (untested).
- memfd: kernel patch 0004 (upstream backport) + the memfd_class policy capability; minigbm's
  shared metadata region is then an allocator memfd that every graphics client maps.
- Android 17 needs `CONFIG_CPUSETS_V1`, `sys.use_memfd=true` (no ashmem upstream), and an audio
  HAL with modules for every instance its VINTF declares, or system_server never finishes booting.
